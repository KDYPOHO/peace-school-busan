# 7개 팀 결재 검토

인자: 검수 대상 경로(파일·폴더·PR 번호)와 선택적으로 산출물 유형. 예) `/dept-review www/` , `/dept-review plan 운영계획(안).docx`

## 0단계. 대상·유형 확정

1. 대상 경로를 확인한다. 유형을 안 주면 아래 기준으로 판단하고 보고서 첫 줄에 "유형 판단: ○○"으로 적는다.
   - `www/`, `android/`, `ios/`, `firestore.rules` → 앱
   - `home/` 또는 누리집 HTML → 누리집
   - .docx·.pdf·계획(안) 문서 → 계획안
   - 포스터·공고·카드뉴스 원고 → 홍보물
   - 공문·협조 요청 → 공문
   - 예산 표만 있는 문서 → 예산
2. 총괄 지침 `CLAUDE.md`를 다시 읽는다.

## 1단계. 무료 자동 점검 (필수, 비용 0)

```
python3 scripts/dept_check.py <대상> --format md
```

- 계획안·공문·보고서는 `--style official`을 붙여 개조식 문체까지 점검한다.

- 결과의 오류·경고를 각 팀 검수 요청에 함께 넘긴다.
- 오류가 있으면 보고서에 그대로 싣고, 팀 검수는 계속 진행한다.

## 2단계. 결재 경로에 따라 팀 서브에이전트를 차례로 호출

| 유형 | 결재 경로 (기안 검토 → 협조 → 최종 검수) |
|---|---|
| 계획안 | quality-team → education-team → finance-team → cooperation-team → legal-team |
| 예산 | quality-team → finance-team → legal-team |
| 홍보물 | quality-team → publicity-team → education-team → legal-team |
| 공문 | quality-team → cooperation-team → legal-team |
| 누리집 | quality-team → it-team → publicity-team → legal-team |
| 앱 | quality-team → it-team → education-team → legal-team |

- 첫 단계는 항상 quality-team(채점표·표기·사실 대조), 마지막은 항상 legal-team, 이후 총괄 결재.
- 서브에이전트는 **한 번에 하나씩, 표의 순서대로** 호출한다. 앞 팀의 보고 요약을 다음 팀 요청에 붙여서, 같은 지적을 반복하지 않고 이관 사항을 이어받게 한다.
- 각 호출 프롬프트에는 ① 대상 경로 ② 유형 ③ 1단계 자동 점검 결과 중 해당 팀 소관 ④ 앞 팀 요약 ⑤ "검수만 하고 파일은 수정하지 말 것"을 넣는다.
- 사용자가 "전 팀"를 요청하면 7개 팀를 모두 돌리되 순서는 quality → education → publicity → it → cooperation → finance → legal.
- 비용 절약: 사용자가 팀를 지정하면 그 팀와 legal-team만 돌린다.

## 3단계. 결재 보고서 작성

`docs/departments/reports/YYYY-MM-DD-<대상 이름>.md`로 저장한다. 양식:

```
# 결재 검토 보고서
- 대상: … / 유형: … / 일시: YYYY. MM. DD.
- 자동 점검: 오류 N건, 경고 N건

## 결재란
| 팀 | 판정 | 상 | 중 | 하 | 미확인 |
|---|---|---|---|---|---|
| 기획·품질팀 | 적합 (92점) | 0 | 1 | 2 | 0 |
| … | | | | | |
| 총괄 | (사용자 결재 대기) | | | | |

## 점검 항목 전수표 (경로상 팀 × 6개 항목, 7개 팀면 42개)
| 팀 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 기획·품질팀 | ✓ | ✓ | ✗ | ✓ | ? | ✓ |

## 우선 조치 사항 (상 등급, 위험도 순)
## 팀별 상세 결과 (각 팀 보고 원문)
## 자동 점검 오탐 판정
## 미확인 항목 (사람 확인 필요, 필요한 자료)
```

## 3-1단계. 총괄 확인 (보고서 저장 전 필수)

- 각 팀 보고에 6개 항목 체크표가 모두 채워져 있는지 확인. 빠진 팀는 그 팀에 다시 요청
- 상 등급 지적은 총괄이 직접 해당 파일:줄을 열어 사실인지 확인하고, 사실이 아니면 "총괄 확인: 오탐"으로 표시
- 팀 간 판단이 엇갈리면 두 의견을 나란히 적고 총괄 의견을 붙임

## 4단계. 사용자 보고

- 보고서 저장 뒤 `/plan-scoreboard`로 점수판에 한 줄 추가한다.

- 결재란 표와 우선 조치 사항 3개 이내만 요약해서 알린다.
- 수정은 사용자가 지시한 경우에만 해당 팀에 "수정" 모드로 다시 맡긴다. 수정 뒤에는 ① `dept_check.py` 재실행 ② 고친 팀 재검수 ③ legal-team 재검수 순서로 확인하고, 상 등급이 0건이 될 때까지 반복한다(최대 3회, 그래도 남으면 사용자에게 보고).
- 머지·배포·외부 게시·공문 발송은 하지 않는다.
