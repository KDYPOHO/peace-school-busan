# 한반도 평화학교 세계 자문협의회 확장 계획

부산 2027 과정은 첫 운영 사례다. 국내·해외 자문협의회가 하나의 한반도 평화학교 앱에 들어와 자신이 참여하는 과정을 찾고, 운영진은 승인받은 협의회의 신청·출결·문의만 관리하는 구조를 제안한다. 기존 부산 참가자는 같은 계정과 수강 기록을 이어서 쓴다.

## 협의회·교육 과정 구성

| 구분 | 운영 기준 | 확인 방법 |
| --- | --- | --- |
| 협의회 목록 | 본부가 확정한 지역회의·협의회 코드, 현지 공식 표기, 활동 여부를 관리한다. 기존 앱의 해외 지역회의 7개 분류를 초기 분류로 검토하고, 협의회 코드는 공식 명부에서 확인한다. | 협의회 이름이 바뀌어도 코드와 예전 수강 기록이 이어지는지 검사한다. |
| 프로그램 | 협의회별로 연도, 모집 상태, 교육 장소, 시간대, 신청 요건, 수료 기준, 심화 정원, 공식 공지의 개정 번호를 관리한다. 부산의 기본 5회와 심화 40명은 부산 과정 설정에 둔다. | 일정과 출결을 개정한 때 Android와 iOS에서 같은 프로그램 개정 번호와 내용을 본다. |
| 일정 | 시각과 IANA 시간대를 함께 보관한다. 참가자에게는 해당 과정의 현지 시각을 먼저 표시하고, 다른 시간대를 쓰는 참가자에게는 기기 시간으로 환산한 값을 함께 표시한다. | 아시아·미주·유럽 등 시간대가 다른 시험 계정에서 날짜 경계, 여름시간 전환, 출석 가능 시간이 맞는지 대조한다. |
| 기관과 권한 | 본부 운영자는 기관과 운영진 권한을 승인한다. 협의회 운영진은 위임된 프로그램과 참가자만 관리한다. 참가자는 자기 신청·출결·문의와 대상에 해당하는 공지만 확인한다. | 국내·해외 협의회 운영진과 참가자가 다른 협의회의 자료를 조회하거나 수정하려는 경우 접근이 거부되는지 시험한다. |

## 언어와 현지 운영

- **하나의 번역 원본.** 한국어 원문과 번역 카탈로그를 GitHub에서 관리한다. Android, iPhone, iPad와 MacBook이 같은 카탈로그를 사용한다. 협의회가 작성한 공지는 원문과 해당 협의회가 승인한 번역문을 함께 저장한다.
- **언어를 고를 수 있게.** 로그인 화면과 내 정보에서 앱 언어를 선택하고 같은 기기에서 유지한다. 기기 언어를 기본값으로 쓰되, 해당 화면의 번역이 준비되지 않았으면 화면에 원문 언어를 표시한다. 언어 이름은 해당 언어의 표기로 표시한다.
- **언어를 단계적으로 연다.** 한국어와 영어를 기준으로 모든 화면을 끝까지 점검한다. 일본어, 중국어 간체·번체, 스페인어, 프랑스어, 포르투갈어, 베트남어, 인도네시아어, 아랍어 등을 해외 시범 협의회 수요와 현지 검수자 확보 순서로 추가한다. 지원 언어를 앱에 표시하는 기준은 참가 신청, 출결, 문의, 탈퇴, 개인정보 안내를 해당 언어로 실제 수행할 수 있느냐다.
- **번역할 범위.** 메뉴, 버튼, 오류, 접근성 읽기, 날짜·숫자, 교육과정, 참가 동의, 개인정보 안내, 수료증을 각각 검수한다. 아랍어처럼 오른쪽에서 왼쪽으로 읽는 화면에서는 탭 순서, 기호와 숫자, 입력 방향까지 확인한다.
- **운영진 답변 도우미.** 초기에는 승인된 안내에서 관련 내용을 찾아 답변 초안과 출처를 보여 준다. 운영진이 내용을 검토하고 직접 보낸다. 참가자 문의 원문과 식별 정보를 외부 모델에 전송하는 기능은 별도 결정이 필요한 후속 범위로 둔다.

## 공통 Firebase 구조와 이전

1. 시험 Firebase에서 `councils/{councilId}/programs/{programId}` 아래에 `applications`, `attendance`, `questions`, `notices`를 둔다. 협의회·프로그램을 지정한 운영진 권한을 계정에 연결한다.
2. 기존 부산 자료는 읽기 전용으로 먼저 대조한다. 동일 계정의 수강번호·출결·문의 관계, 자료 수, 사례별 결과가 일치하는지 확인한 뒤 시험 환경에서 복제한다. 실제 운영 이전은 검증된 백업, 복구 시험, 담당 기관 확인을 거친다.
3. 새 프로그램에는 현지 담당 기관, 문의 창구, 처리 목적, 열람·정정·삭제 절차와 보유 기간을 설정한다. 운영할 국가와 기관, Firebase 저장 위치와 국외 이전 조건은 실제 운영 범위를 정한 뒤 기관이 검토한다.
4. 현장 장애가 나면 운영진이 수강번호로 출결을 처리할 수 있게 한다. 데이터 연결이 돌아온 뒤 저장 성공 여부를 보여 준다. 출석과 답변의 중복 쓰기는 서버에서 한 번만 적용한다.
5. 애플과 안드로이드가 같은 시험 계정에서 동일한 문의 답변, 수료 기준, 공지 개정 번호를 읽는지 비교한다. 테스트에는 가상 계정과 예시 데이터만 쓴다.

## 배포 단계

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 부산 내부 시험 | 현재 운영진·참가자 화면, 휴대폰·태블릿, Apple Silicon MacBook | 문의와 답변, QR·수강번호 출석, 화면 확대, 가로·세로 레이아웃, 같은 콘텐츠 확인 |
| 해외 내부 시범 | 다른 시간대의 협의회 두 곳 이상, 한국어·영어, 각각의 운영진 | 협의회 간 자료 격리, 현지 시간 표시, 알림과 답변, 삭제 처리, 운영 인수인계 시험 |
| 지원 확대 | 검수된 언어와 협의회부터 순차 확대 | 언어별 핵심 흐름·법적 안내·접근성 점검, 개정 이력과 장애 대응 담당자 확인 |

Apple Silicon MacBook은 Xcode의 iPad 앱 실행 경로를 우선 검증한다. Intel MacBook은 같은 계정을 사용하는 웹을 제공하는 안으로 잡는다. Intel용 Mac App Store 배포가 필요하면 Mac Catalyst를 별도 검증한다. Android 태블릿은 Google Play의 같은 패키지, iPhone과 iPad는 동일한 TestFlight 빌드를 사용한다.
