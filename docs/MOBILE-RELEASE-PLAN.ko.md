### 변경 파일과 영향

- `www/js/config.js`, `www/js/faq.js`는 확정된 회차·정원·마감 시각·표시 버전을 공통 반영한다. 앱 안내와 모집 문구가 같은 날짜를 쓰는지 대조한다.
- `www/js/app.js`, `www/js/backend.js`, `firestore.rules`는 온라인 출석 인정 시간과 참가 자격, 수료, 최종 40명 정원의 일관성을 검증한다. 기존 신청·출결·심화 지원 레코드와 운영진 상태를 읽을 수 있는지 점검한다. 상태 모델을 변경하면 기존 레코드의 해석과 복구 절차를 변경 PR에 적는다.
- `android/app/build.gradle`, `ios/App/App.xcodeproj/project.pbxproj`는 공통 후보의 표시 버전을 맞추고 플랫폼별 고유 빌드 번호를 부여하는 파일이다. QR 권한 차이가 관찰되면 Android Manifest와 iOS `Info.plist`의 설정만 관련 범위에서 확인한다.
- Firebase 에뮬레이터 설정과 규칙 테스트 파일은 검증 경로를 정한 뒤 변경 PR에서 확정한다. AI Studio 시험 복사본용 파일이 필요한 경우 공통 앱 소스와 분리하고, 원본으로 가져올 파일과 근거를 PR에 명시한다.

AI Studio의 루트 Gradle 진입점을 검토할 때에는 먼저 Android 앱 모듈, `@capacitor/android` 의존성, 동기화가 생성하는 Cordova 모듈의 경로를 확인한다. 이어서 웹 자산 매핑, Gradle·SDK 호환성, 시험 서명과 APK 출력 위치를 검증한다. Argon과 Neon이 제안한 루트 설정은 시험 복사본에서 검증할 후보 단계다.

## 3. Android와 iPhone이 같은 내용이라는 검증

1. **패키지 비교** — 동일 후보 SHA의 `www/` 파일별 SHA-256 목록을 만든다. Android APK의 `assets/public/`, iOS 앱 번들의 `public/`에 들어간 해당 경로의 내용 해시를 각각 원본과 대조한다. Capacitor가 만드는 플랫폼 메타데이터는 별도 기록한다. 각 빌드의 버전, 빌드 번호, 앱 식별자, 파일명, 빌드 SHA를 함께 남긴다.
2. **참가자 흐름 비교** — 같은 시험 계정으로 Android에서 참가 신청을 저장한 후 iPhone에서 읽는다. iPhone에서 변경한 시험 프로필이 Android에도 표시되는지 확인한다. 일정·공지·수강증 QR·출결 숫자, 3회와 4회 출석의 심화 지원 상태를 두 기기에서 대조한다. 역방향으로도 한 번 실행하고, 시험 DB에 기록된 문서의 필드와 상태 전이를 함께 확인한다.
3. **운영진·예외 비교** — 두 기기에서 각각 QR 카메라 권한 허용·거절·재허용, 잘못된 QR과 중복 스캔, 수강번호 직접 입력을 확인한다. 네트워크 장애에서 안내·재시도 후 중복 여부, 앱 종료 후 재실행, 강제 종료 뒤 로그인 복원, 큰 글씨와 세로·가로 화면을 확인한다.
4. **데이터 경계 확인** — 미승인 회차·시간대의 출석, 다른 참가자의 기록 접근, 비운영진의 운영진 기능, 탈퇴 후 기록 조회를 테스트한다. 정원 39명에서 두 운영진이 동시에 다른 사람을 확정해 최종 40명인지 확인한다. 포기·예비 충원은 마감 전후와 반복 입력을 검증한다.
5. **기록 형태** — 동일 사례별로 예상 결과, Android 결과, iPhone 결과, 장치/OS, 후보 SHA, 네이티브 빌드 번호, 가상자료 스크린샷을 남긴다. 재현할 수 있는 오류 요약과 검증 환경을 남기고 시험 계정 인증정보나 실제 신청 내용을 기록에서 제외한다.

## 4. Firebase 적용 기준

- **운영 환경**은 현재 앱의 로그인·데이터 처리 환경이다. 배포 설정과 개인정보 처리 절차를 정식 운영 승인 시점에 다시 확인한다.
- **시험 환경**은 출석·신청·공지·문의·심화 기록을 가상자료로 검증한다. 규칙 검사는 Emulator Suite에서 반복하고, 두 실기기의 동기화는 같은 별도 시험 프로젝트에서 비교한다. 승인된 시험 환경이 아직 없다면 브라우저의 체험 모드와 에뮬레이터 결과까지만 기록한다.
- 동일 정책을 웹·Android·iOS에 적용하되 QR 권한과 로그인 제공 방식의 실제 차이는 플랫폼별로 명시한다. 심화과정의 최종 선발 판단은 운영위원회가 담당한다.
